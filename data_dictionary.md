# Data Dictionary

## SaaS Product Analytics & Churn Prediction

This document describes the structure, meaning, and intended use of all raw datasets used in the project.

The datasets are **synthetically generated for educational and portfolio purposes**. They simulate a realistic SaaS business environment containing users, product usage events, subscription activity, and customer support interactions.

---

## 1. Dataset Overview

| Dataset | Grain | Approx. Rows | Primary Key | Purpose |
|---|---|---:|---|---|
| `users.csv` | One row per user | 30,000 | `user_id` | Customer and user profile information |
| `events.csv` | One row per product event | 1.55M+ | `event_id` | Product usage and behavioral activity |
| `subscriptions.csv` | One row per user subscription | 30,000 | `subscription_id` | Subscription, revenue, and churn information |
| `support_tickets.csv` | One row per support ticket | 9,976 | `ticket_id` | Customer support experience |

---

# 2. `users.csv`

## Purpose

Contains the core profile information for users of the fictional SaaS platform.

The table represents the **user dimension** and is used as the central reference table for product usage, subscriptions, and support activity.

## Grain

**One row = one user**

## Primary Key

`user_id`

## Columns

| Column | Data Type | Description |
|---|---|---|
| `user_id` | String | Unique identifier for each user |
| `company_id` | String | Identifier of the company the user belongs to |
| `signup_date` | Date | Date when the user registered |
| `country` | String | User's country |
| `industry` | String | Industry of the user's company |
| `company_size` | String | Size category of the company |
| `acquisition_channel` | String | Marketing/acquisition source through which the user joined |
| `plan` | String | User's current SaaS plan |
| `role` | String | User's role within the company |
| `primary_device` | String | User's primary device |
| `engagement_propensity` | Numeric | Synthetic behavioral propensity score between 0 and 1 used to simulate realistic engagement |
| `onboarding_completed` | Boolean | Indicates whether the user completed onboarding |

8. Data Quality Expectations

Before analysis, the following checks should be performed.

Users
user_id should be unique.
user_id should not be null.
signup_date should contain valid dates.
engagement_propensity should be between 0 and 1.
onboarding_completed should contain Boolean values.
Events
event_id should be unique.
user_id should exist in users.csv.
event_timestamp should be valid.
Events should occur on or after the associated user's signup date.
session_duration_minutes should not be negative.
Subscriptions
subscription_id should be unique.
user_id should exist in users.csv.
Subscription end dates should not precede start dates.
MRR should not be negative.
tenure_days should not be negative.
Support Tickets
ticket_id should be unique.
user_id should exist in users.csv.
resolved_at should be after created_at when present.
resolution_time_hours should not be negative.
Satisfaction scores should be between 1 and 5.
9. Synthetic Data Disclaimer

All datasets in this project are synthetically generated.

They are designed to simulate realistic SaaS business behavior for:

Portfolio development
Data analytics practice
Product analytics
Machine learning
Business intelligence
Customer retention analysis

The data does not represent actual customers, companies, or transactions.

The synthetic generation process intentionally introduces behavioral relationships between product engagement, subscription activity, support interactions, and customer churn so that meaningful analytical and machine-learning questions can be investigated.
